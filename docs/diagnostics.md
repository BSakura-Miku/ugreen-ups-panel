# 诊断与原始观察

v0.8.0 在「诊断与说明」页提供连接检查、系统 UPS 原值、组件版本和短时 A/B 观察。先更新宿主机采集器，再更新面板，才能获得完整元数据。旧采集器仍兼容；缺失项显示未知，不从设备型号推断固件或环境。

## 连接检查的含义

| 检查 | 能说明什么 |
| --- | --- |
| 采集器快照 | 最近是否读到有效心跳 |
| 宿主采集条件 | 采集器报告的 Linux 与 Python 条件；不是容器内的系统信息 |
| USB 设备识别 | 是否找到目标设备，是否存在多设备选择问题 |
| 被动采集入口 | 宿主机上的 usbmon 节点是否存在、是否可读 |
| 私有报文接收 | 是否收到完整且新鲜的 `0x71` 报告；没有目标活动、没有所需中断输入、报告不完整和字段无效分别统计 |
| 系统 UPS 查询 | 最近一次 NUT `upsc` 查询是否成功 |
| 两路设备关联 | 本地 NUT 查询的序列号和 USB 标识是否能与采集对象核对；缺少依据或远程目标为未确认 |
| 历史写入 | 面板最近一次数据库写入是否成功，和实时采集分开判断 |

USB 样本与采集心跳的有效期都是 10 秒；NUT 查询有效期为 45 秒。NUT 时间表示软件**完成查询**的时间，不能证明 UPS 内部何时更新变量。NUT 能返回电量，也可能没有产生面板所需的完整私有报告。

`pollonly` 只根据 NUT 明确报告的开关显示；缺少该变量时为未知。它可能解释为何没有中断输入，但页面不会据此改动配置或认定唯一原因。详细接收计数统计最近 60 秒，计数是采集事件而不是电气测量次数。

## 系统报告与原值

低电量（`LB`）、需要换电池（`RB`）、过载（`OVER`）、活动告警（`ALARM`）、强制关机流程（`FSD`）和输出关闭（`OFF`）均标为系统报告。NUT 状态、告警文字和低电量/续航阈值用于对照系统配置，不替代 NAS 的保护逻辑。`OL DISCHRG` 表示系统同时报告在线与放电，应结合两路查询时间和私有模式核对。

`battery.runtime` 保留原字符串，并独立标示质量。`-1`、`65535`、`4294967295` 视为疑似占位，不换算成小时；无效、缺失和过期值也不作为当前剩余续航。可解析秒数仍为系统报告、尚未独立验证，不能作为本项目的容量测试结果。

## A/B 短时观察

A/B 对应报告的零起始字节偏移 26、27；相邻字节 28 也保留在观察导出中。当前仅有数值表现与间接线索，尚未证明是温度传感器读数，也未确认缩放、符号或位置。因此页面继续写「疑似温度，未验证」，使用无单位整数，不标 `℃` 或具体探头。

后台独立观察快照，浏览器未打开时也会累计；刷新或下载不制造采样。内存最多保留最近 60 分钟、4096 点，页面可选 15/60 分钟，并显示实际首末时间及样本数。只保存采集器发布过且被观察到的样本，不保证捕获每一条 USB 报告。数据库不可写时仍能观察；容器或服务重启后重新开始，不回填旧数据。

同一上下文及时间戳的重复样本不重复记录。模式、设备、来源、解码器、公式或校准上下文变化后分段；超过 5 秒的采样缺口、无效或失鲜输入、时间倒退也会中断连线。时间回拨时按非递减观察时钟管理保留窗口，点的时间戳保持原样。失鲜立即隐藏当前 A/B 值，窗口内的旧点仍可核对。

CSV 同行包含时间戳、段号、随机设备别名、来源、模式、原状态字节、A/B 与字节 28、电量、电池组/输入/输出电压及电流候选、解码/公式版本、校准身份。候选电流与字节值仍是协议观察，不因导出而获得测量精度保证。

## 版本与诊断下载

页面分别显示面板和采集器的版本、可用的 Git 修订号与 Python 模块源码 SHA-256 指纹；指纹帮助区分同名版本的源码内容，不代表发布者签名。未提供修订号时保持为空。NUT 驱动及 UPS 固件使用实际报告值，USB `bcdDevice` 作为设备版本独立显示，不能直接等同于固件版本。

「下载诊断 JSON」包含版本、分层检查、安全系统原值及所选观察窗口；「下载观察 CSV」只包含相同窗口的固定观察列。导出通过字段白名单构造，排除序列号、主机与网络地址、USB 路径、NUT 查询目标、自由告警文字、制造商/型号自由文字及完整原始报文；设备使用进程内随机别名。CSV 不接受任意设备文字作为单元格，避免公式形式的内容进入导出。

页面可为本机排查显示受限的系统原值，**下载文件与 `/api/live` 原始响应不同**。需要分享时优先使用诊断下载，并查看文件内容。下载仅保存到浏览器，不自动上传、发帖或发送给第三方。

| 只读接口 | 内容 |
| --- | --- |
| `GET /api/diagnostics?minutes=60` | 当前诊断与短时观察，窗口接受 1–60 分钟 |
| `GET /api/diagnostics/export.json?minutes=60` | 白名单诊断包 |
| `GET /api/diagnostics/export.csv?minutes=60` | 固定列观察明细 |

## 宿主机自检

默认安装使用 `/opt/ugreen-ups-panel/current` 指向当前采集器源码。升级后在 **NAS 宿主机**运行：

```sh
cd /opt/ugreen-ups-panel/current
sudo python3 -m ups_panel.doctor
```

默认读取已有快照、本项目的设备选择设置、sysfs 与依赖状态，并进行一次只读 NUT 查询。输出为白名单 JSON，可重定向保存到自己的目录。它只依赖 Python 标准库，无需安装面板的 Web 依赖。若使用自定义安装路径，可从 `systemctl show -p WorkingDirectory ugreen-ups-collector.service` 查看实际源码目录。

已有快照无法验证私有采集时，可显式增加最多 60 秒的被动观察；已有新鲜快照时直接使用快照：

```sh
sudo python3 -m ups_panel.doctor --observe-seconds 10
```

自检不加载内核模块、不更改 NUT 或关机配置、不重启服务，也不打开 USB 控制接口；可选观察只读取已有 usbmon 节点。无数据时依次核对输出中的宿主条件、设备、入口和私有报告状态。它能定位缺少哪类证据，不保证自动找出硬件故障。`--nut`、`--serial` 与 `--snapshot` 可选择既有对象，具体参数见 `--help`。

已有历史数据库与校准文件不因 v0.8.0 诊断功能而迁移或重算；升级流程与备份见 [README](../README.md#更新)和[架构文档](architecture.md#备份与维护)。
