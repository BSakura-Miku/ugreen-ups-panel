# 验证范围

项目将软件行为验证与电气测量验证分开记录。软件通过回放或自动化测试，不意味着 USB 中的每个候选字段都完成了物理定标。

## 已有实机观察

验证环境为一台 Linux x86_64 NAS、US3000、19 V 适配器及原系统 NUT 驱动。

- 被动 usbmon 能持续接收完整 `0x71` 报告，已观察到单次事件含一帧或多帧。
- 外部供电、充电、电池供电三个状态都有实际记录；充电记录包含电量持续上升。
- 在供电切换记录中，偏移 16 符合输入衰减/恢复，偏移 18 符合约 19 V / 12 V 输出切换。
- 采集器和面板更新期间，原 UPS 保护服务保持运行；项目的启动、停止和回退不需要停用原驱动。
- 采集停止后页面能进入过期状态；容器重建后历史卷保留数据。
- 经验功率模型经过有限范围的同步参考比较，证据和限制见[校准说明](calibration.md)。

这些观察支持该环境下的可用性，不构成其他 NAS 系统、固件、电池状态或适配器的兼容性承诺。

## 自动化检查

项目测试覆盖以下行为，具体以当前测试文件和执行结果为准：

- 协议完整性、已记录模式、无效值及候选字段的条件显示。
- usbmon 状态、总线、设备、端点过滤，合并报告、截断和设备发现。
- 模型的显式配置、预热、尾随平滑、断连、状态切换及适用范围。
- 校准 schema 1 哈希兼容、schema 2 电压匹配与可空系数、旧页面/采集器能力检查。
- 手工助手的 30 秒/12 点窗口、按时间戳去重、身份变化重置、10% 波动门槛、低回充功率拒绝和冻结窗口重算。
- 快照有效性、新鲜度、历史去重、加权聚合、三层保留周期及不同模式/校准配置隔离。
- 长期查询的 UTC 日边界、已有历史回填和实际记录跨度；CSV 均值与极值保持对应。
- 电池供电记录的起止判定、重复/倒序样本、重启续接、采集中断、SOC 反弹及跨查询边界的统计口径。
- 电芯连续待机的 30 分钟观察、参考区间的 120 秒确认，以及 20/50/100 mV 分界和浮点边界；等级变化或单次尖峰期间不沿用先前确认等级。
- 压差按四节电芯重算；充放电、失鲜、无效读数、超过 5 秒的间隔、倒序及设备/来源/解码身份变化重置观察。重复样本和只读查询不增加时长，近期峰值与最常单独偏低电芯只统计最近连续待机窗口。
- 逐次电池端能量使用未平滑原始功率与有效电池倍率按实际时间做梯形积分；5 秒积分边界、无效功率、重复/倒序、缺口及依据变化不被补齐或混算。
- 能量与会话游标同事务写入、失败回滚及重启续接；降级后再升级时核对连续性，旧明细没有能量时保持空值，查询不修改积分状态。
- 能量覆盖率与会话完整性分开表示，恢复外电后的 SOC 不进入能量端点；无有效区间不显示为 0 Wh，非有限结果不进入 JSON，跨查询边界不按时长分摊 Wh。
- 前端区分缺值、有效零值和很小的估算值，部分覆盖不会被显示舍入为 100%；未知状态使用中文回退，旧 API、观察中、充放电与失鲜均不显示不适用的确认等级。
- API、CSV 与数据库失败时的隔离处理。
- A/B 字节的有界内存窗口、上下文分段、同时间戳冲突、时钟回拨与纯只读查询；数据库故障不阻塞观察，失鲜不显示旧值作为当前读数。
- 分层连接状态、NUT 报告告警与阈值、45 秒查询有效期及续航占位值处理；缺少采集器元数据时保持未知。
- 诊断 JSON/CSV 的固定字段白名单、任意文字/地址/设备标识排除，以及宿主机自检默认不进入被动读取、显式观察时的持续时间和事件数上限。

```sh
.venv/bin/python -m pytest -q
npm --prefix frontend test
npm --prefix frontend run build
docker compose config --quiet
```

回放只使用文件，不打开 USB；软件测试不执行 NAS 重启、USB 拔插、市电切换或 UPS 控制命令。

半年、一年功能表示可保存和查询的时间范围，不代表项目已经完成一年连续实机运行验收。长期时间边界可用构造记录验证，真实历史仍以页面显示的记录日期为准；升级只补建尚存的旧数据，不能恢复早已删除的历史。

电池供电明细从升级后首次有效采样开始，不从旧事件或聚合历史回填。确认“完整”需观察到进入和退出电池供电的全过程；缺少起止、离线、超过 10 秒的采集缺口或未知模式都应标记不完整。次数、观测时长与 SOC 净下降各按自己的范围规则统计，不能把不完整记录当作完整耗电结果。

v0.7.0 的 Wh 从具备有效功率依据的新记录开始计算，不回填旧记录。能量区间要求相邻样本不超过 5 秒，这比供电会话的 10 秒缺口条件更严格；因此完整供电记录也可能只有部分能量覆盖。即使观测区间全部覆盖，也只代表首末电池供电样本之间的估算，并不表示完成从满电到截止的容量测试。详细口径见[电芯一致性与放电能量参考](battery-observation.md)。

## v0.7.0 界面验收范围

合成场景用于核对桌面与窄屏界面，包括已确认的待机参考等级、等级观察中、充电、失鲜，以及完整覆盖、部分覆盖、未校准和旧能量空值等逐次记录。检查项目包括：

- 待机观察与等级确认进度、最常偏低电芯、窗口峰值及可展开的参考阈值说明；7 天和 30 天入口切换已有压差均值/峰值趋势。
- 充放电只展示工况与原始压差，失鲜隐藏实时数值和评级，不能借用上一组数据的确认等级。
- 每条 Wh 始终标为估算，覆盖时长、功率依据、能量端点和缺口原因可核对；旧记录与缺少电池倍率时显示明确说明，不显示虚假的 0 Wh。
- 跨范围记录保留该次观测口径，页面不提供混合依据的范围总 Wh；窄屏记录保持可读且没有横向溢出。

合成场景可以使用带有完整时间跨度的构造样本检验状态，不需要降低生产的 30 分钟、120 秒或 5 秒门槛。这类验收只证明界面与软件规则能处理相应输入，不证明真实电芯故障、容量衰减、测量精度或完整电源保护链已经通过实机验证。

## 安装后的基本核验

v0.8.0 诊断页通过合成快照与真实后端接口进行 1440、768、390 像素宽度的浏览器核验：版本指纹、系统告警与续航占位值、A/B 阶梯线和工况/缺口分段、15/60 分钟范围及 JSON/CSV 下载均可核对；旧采集器、失鲜和异常可选元数据不会冒充当前有效结果。下载检查覆盖设备标识、查询目标、地址、告警自由文字和完整帧的排除，页面无横向溢出或脚本错误。这些仍是软件输入验证，不是温度或电源故障实验。

1. 确认原 NAS UPS 管理页面和保护服务正常，再安装本项目。
2. 确认采集器为运行状态，页面来源为 USB 实时采集且时间持续更新；不要将回放来源用于真实监控。
3. 确认输入、输出及电池电压分别显示，缺少模型时功率明确表示未配置。
4. 等待至少一个历史提交周期，切换 30 天、半年与一年，核对实际记录日期及完整横轴；未采集时段应留空。对照电芯压差均值/峰值与 CSV，确认没有存储错误。
5. 核对电池供电明细的开始记录时间和默认 90 天范围；若尚无电池供电观测，应显示无记录，不要求通过断电制造记录。已有明细中，检查不完整标记、SOC 反弹与次数/时长/净下降口径。
6. v0.6.0 先升级宿主机采集器，再更新面板。确认助手根据适配器输入预选电压，未配置的回充/电池系数留空，保存后需等新鲜采集确认。更新前保留配置与数据库备份，更新后再次检查原 UPS 保护服务。
7. v0.7.0 可继续使用已安装的 v0.6.0 采集器。更新面板后，在自然的连续待机过程中检查观察进度，确认未达到条件时没有评级；查看已有供电记录的 Wh、覆盖率与依据，不要求通过断电制造能量记录。旧能量空值应继续保留。
8. v0.8.0 完整诊断需更新采集器与面板。在「诊断与说明」核对各自版本、USB 和系统查询状态，观察自然累积的 A/B 点并查看白名单下载；不要求通过断电、加热或拔插设备制造变化。旧采集器缺少的检查显示未知。

## 尚未形成通用保证的部分

- 多批次、多固件、其他 CPU 架构和不同 NUT 驱动的私有报告兼容性。
- 输入/输出电压及电流的实验室级绝对精度，电池容量、SOH 和剩余续航。
- 字节 26/27 是否来自温度传感器、缩放方式与物理位置；有原始趋势不等于已证实温度读数。NUT 告警也只是系统报告，未据此完成硬件故障验证。
- 新增 12/20 V 自定义配置和手工助手的实机功率精度；支持选择电压与通过软件测试不代表已完成这些接线下的仪表验证，原 19 V 样机证据不能直接套用。
- 电芯压差参考分界未获厂家验证，也不是容量、SOH 或故障标准；逐次 Wh 仍受电池倍率、SOC/标称容量假设及原始测量误差限制，没有因此形成独立容量测量。
- 所有 NAS 系统升级、内核更换、实际 USB 热插拔和整机重启后的行为。
- 长期运行资源上限，以及 NAS 原有自动关机保护的完整硬件验收。

请勿把“硬件具备功能”“代码包含重连处理”或“一次演示成功”改写为已通过全部真实故障场景。

## v0.9.0 采集器更新验证

新增验证覆盖固定发行来源、SHA校验、USTAR/gzip安全解析、版本及源码指纹、错误密钥和同源限制、只读状态、重复提交、下载期间手动升级、失败恢复、持久操作结果、Unix socket权限与可选Compose挂载。安装器通过模拟systemd和临时文件验证保留原配置、源代码切换、锁内指纹、SIGTERM恢复及安装服务失败回退。

实机验收采用正常正式发行包，不向UPS发送控制指令，也不通过断电或损坏固件验证恢复。强制断电中断升级不保证自动完成事务；重启后标记被中断并重新读取当前版本，需要核对采集是否恢复。

## v0.10.0 界面与查询验证

紧凑布局通过真实后端与明确标识的合成快照，在 1440 像素桌面和 390、360 像素窄屏中核对。覆盖总览、诊断、校准及硬件说明，检查趋势与电芯表的布局、导航和范围选择、实际记录日期、CSV 范围，以及供电记录的完整性和能量覆盖说明。

电池供电和待机高压差场景核对跨页醒目提示与电芯定位；充电、观察未完成和失鲜场景核对不显示不适用的确认等级。更新服务失败时，错误在管理表单收起后仍可见；管理表单关闭、页面切换或服务不可用时清空输入的密钥。所有场景使用软件输入，没有切换真实 UPS 供电或执行真实更新请求。

历史与事件轮询覆盖页面切换、标签隐藏、恢复及卸载取消；原生定时器接收者回归测试和浏览器连续刷新检查防止首次查询后停止刷新。查询优化用固定数据逐字段比较原有输出，覆盖上下文分组、时间边界、缺值及浮点值，并验证 WAL 历史读取期间新样本、供电记录和 Wh 仍能提交。

一年数据规模、单次查询、并发查询和旧数据回填的合成实测见[存储与查询性能](STORAGE.md)。这些结果说明测试数据和设备下的性能，不代表已经完成一年连续实机运行；半年和一年仍是日统计，无法恢复早已过期的秒级细节。


## v0.11.0 相对容量参考验证

新增固定基线模型、Store 事务及 HTTP 边界测试，覆盖 90%→80% 精确边界、未平滑倍率积分、60 秒最短区间、5 秒连续性、SOC 跳变及回升、按时间加权负载波动、平均负载匹配、独立供电周期、最近三次中位数及超过 100% 的参考值。重启不拼接未完成区间，清理旧趋势不移除基线。

重建参考测试覆盖归档与主状态同事务、写入失败后内存及数据库恢复、旧参考 ID 冲突、等待写锁后再读新鲜采样、拒绝落后的采样，以及同源、自定义请求头、JSON 格式和请求大小限制。GET 不形成新观测。

前端展示测试覆盖缺少基线时不显示 100%、基线不计入后续三次比较、离线历史日期、接口失效和依据不兼容时隐藏当前指数、只使用与后端一致的匹配中位数。前端异步读写响应的代次隔离另经代码审查。

上述算法数据为合成数据，不是 US3000 的长期衰减实测。60 秒、负载波动 15% 和平均负载差 10% 是项目比较门槛，不是厂家健康标准；当前没有已验证的温度字段。发布后真实设备可以保持基线建立中，直到自然产生合格区间，详见[相对容量参考](battery-capacity.md)。

## v0.12.0 用电统计验证

新增测试覆盖市电输入估算功率的梯形积分、北京时间小时与零点边界、真实零值和缺采空值、超过 5 秒的间隔、重复与倒序采样，以及模式、设备、来源和校准依据切换。月日均只使用已结束的完整记录日；电池供电期间市电用电按有效零值记录，不重复计入放电能量。

账本测试覆盖与历史同事务提交、失败后继续采样并重试、提交成功但未确认、重启与降级再升级、缓冲上限和只读查询。清理旧趋势不删除用电账本，旧历史不回填。日期接口拒绝无效月份或日期，未来及未记录日期保持空值。

真实后端以明确标识的合成采样回放驱动，在桌面及 390、360 像素窄屏中核对跨月导航、键盘选日、完整日与缺采日、24 小时功率图、离线保留累计、未配置功率及接口失败状态。缺采小时留空，已有累计不会因离线被显示为零，页面没有横向溢出。

发布前完整 Python 测试 1,065 项、前端测试 88 项及生产构建通过。以上验证说明软件对所给采样的统计与展示行为；用电量仍是经验功率模型的积分估算，不代表经过独立电表定标。详细口径见[用电统计](energy-usage.md)。
