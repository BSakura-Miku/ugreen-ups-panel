# US3000 Power Monitor

[简体中文](README.md) | English

<p align="center"><img src="frontend/src/assets/us3000-logo.png" width="80" height="80" alt="US3000 Monitor logo" /></p>

![US3000 dashboard preview with demonstration data](docs/assets/dashboard-demo.png)

*The preview uses local demonstration data and the device label DEMO. It contains no real NAS telemetry or device serial number. The application UI and detailed documentation are currently primarily in Simplified Chinese.*

An unofficial, read-only UGREEN US3000 dashboard for Linux NAS systems. It displays power state, battery charge, cell voltages, input/output voltages, and historical trends. A host-side collector uses Linux usbmon to observe traffic already generated by the existing UPS driver; a Docker container serves the dashboard and read-only API.

The running dashboard does not depend on a smart plug, Home Assistant, or an external CDN.

This is a community project, with no affiliation with or certification from UGREEN. **The NAS's existing UPS service remains responsible for power-loss protection and shutdown. This project does not provide power protection.**

## What you can monitor

| Feature | Nature of the data |
| --- | --- |
| External power, charging, and battery power states | Device states observed during transitions on one US3000 |
| Charge percentage, input/output voltage, pack voltage, and four cell voltages | Device-reported values with range checks |
| Cell voltage difference | Highest minus lowest cell voltage; not battery state of health |
| Battery charge/discharge current and power | Provisional private-protocol interpretations; measurement location or scaling remains uncertain |
| AC input and battery power estimates | Optional empirical models from one installation, disabled by default |
| Trends, power/connection events, and CSV export | Local SQLite aggregates; missing values remain empty |
| Hardware reference and advanced diagnostics | Product/teardown information, source links, raw fields, and NUT status |

There are no remote-shutdown, smart-plug control, UPS parameter-write, or automatic power-cut features. Unverified temperature, load percentage, remaining runtime, and battery health are not presented as valid measurements. Power estimates are not readings from a DC power meter; see the [calibration documentation](docs/calibration.md).

## Compatibility and prerequisites

- Linux x86_64, systemd, Python 3.10+, and Docker Compose v2. Hardware validation currently covers one US3000 with a 19 V adapter; other architectures and firmware versions need validation.
- A kernel with usbmon support and working `/dev/usbmonN` devices. The collector uses the binary interface; the dashboard does not need debugfs or USB devices mounted into its container.
- An existing NUT/system UPS driver connected to the UPS and continuously reading complete private `0x71` reports. **NUT being able to display charge percentage does not prove that it reads these reports.** This project does not actively request them.
- Device discovery matches USB VID:PID `2b89:ffff`. If several matching devices are attached, select one explicitly by serial number.
- The dashboard and API have no built-in login and bind to `127.0.0.1` by default. Limit LAN access to trusted networks; use an authenticated reverse proxy or a VPN for remote access.

## Deployment

Clone the repository, then run the commands from its root directory. Installing the host collector requires root. The scripts install and restart only this project's services.

```sh
git clone https://github.com/BSakura-Miku/ugreen-ups-panel.git
cd ugreen-ups-panel

# 1. Install the host collector.
# Installation fails if no new report arrives during validation.
# An upgrade attempts to restore the previous collector if validation fails.
sudo sh scripts/install-collector.sh
systemctl status ugreen-ups-collector.service

# 2. Build and start the dashboard. It initially listens only on the NAS itself.
cp .env.example .env
docker compose up -d --build
docker compose ps
```

The default port is `9086`. To allow LAN access, edit `UPS_BIND_IP` in `.env` to the NAS's actual LAN address, then run `docker compose up -d` again. This `.env` file configures Compose only. Host collector settings belong in `/etc/ugreen-ups-panel.env`.

A first installation uses calibration profile `none`, so it does not apply coefficients derived from the development unit. Upgrades preserve existing configuration. To select a device or change the NUT target, edit `/etc/ugreen-ups-panel.env` and restart this project's collector. Do not commit serial numbers or local configuration to the repository.

```ini
UPS_CALIBRATION_PROFILE=none
# UPS_SERIAL=your-device-serial
# UPS_NUT_TARGET=your-ups-name@localhost
```

```sh
sudo systemctl restart ugreen-ups-collector.service
curl --fail http://127.0.0.1:9086/api/health
```

`service: ok` means that the HTTP service is responding; `capture_fresh` indicates whether telemetry is current. The UI reports capture, NUT lookup, and history-storage status separately. Container health is not a substitute for checking the NAS's UPS protection service.

The container runs as UID `10001`, with a read-only root filesystem and all capabilities dropped. It reads the snapshot directory and writes only to its own data volume. The collector runs as a root service restricted by systemd because it needs host usbmon access. usbmon observes a USB bus before the application filters for the target device, so this permission is broader than access to a single UPS. See [security notes](SECURITY.md).

### Optional power model

`local-19v-v1` retains an empirical AC-input model and a battery-power estimate from one installation. It is **not a universal US3000 calibration profile**: matching the model number and adapter voltage does not establish accuracy on another system. Adapter efficiency, firmware, battery aging, and actual capacity can change the result.

Only enable it if you intentionally want to evaluate that model and understand its limits:

```sh
sudo sh scripts/install-collector.sh --calibration-profile local-19v-v1
```

Use `--calibration-profile none` to disable it again. The AC estimate includes empirical charging compensation and an 8-second trailing average; the battery estimate relies on a nominal-capacity assumption. Neither establishes the actual DC power delivered to the NAS or calibrates the raw output-current field. The formulas, validation ranges, and assumptions are documented in [Power calibration](docs/calibration.md).

## Local demo and development

Replay mode works without a UPS, is visibly marked as a demo, and does not query NUT. Local frontend development requires a compatible Node.js version; Node.js 22.12+ is suitable for the current Vite toolchain. Docker builds include their own Node runtime.

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock -r requirements-dev.txt
npm --prefix frontend ci
npm --prefix frontend run build

# Terminal 1
.venv/bin/python -m ups_panel.collector --replay fixtures/online.hex --output runtime/latest.json

# Terminal 2: use exactly one backend worker per database
UPS_SNAPSHOT=runtime/latest.json UPS_DATABASE=runtime/history.sqlite \
  .venv/bin/uvicorn ups_panel.app:app --host 127.0.0.1 --port 8765
```

Open `http://127.0.0.1:8765`. For frontend hot reload, additionally run `npm --prefix frontend run dev`; the development proxy forwards `/api` to port `8765`.

```sh
.venv/bin/python -m pytest -q
npm --prefix frontend run build
docker compose config --quiet
```

## History and backups

- On the validated device, reports arrive approximately every 2 seconds. A sample or collector heartbeat older than 10 seconds is marked stale.
- The database retains 10-second aggregates for 7 days, 60-second aggregates for 90 days, and events for 180 days. There is currently no UI for changing retention periods.
- History queries are downsampled for the requested time range. CSV contains those queried aggregates, **not every raw USB report**.
- Aggregates are committed approximately every 10 seconds. An unexpected power loss can lose the most recent commit interval. Different measurement locations, models, and quality states remain separate; old values are not recalculated.
- Persistent write failures use a bounded pending queue that prioritizes recent data. `storage_dropped_buckets` reports buckets discarded as a result. A disk failure does not cause an unlimited in-memory backlog.
- Raw USB bus traffic is not recorded indefinitely. Do not delete `/run/ugreen-ups-panel` while the application is running; the container bind mount depends on it.

For an online backup, use SQLite's backup API instead of copying only the database's main file while it is being written:

```sh
docker compose exec -T panel python -c "import sqlite3; s=sqlite3.connect('/data/history.sqlite'); d=sqlite3.connect('/data/backup.sqlite'); s.backup(d); d.close(); s.close()"
docker compose cp panel:/data/backup.sqlite ./backup.sqlite
```

To restore, stop `panel`, replace `/data/history.sqlite` in its data volume with the backup, remove old `history.sqlite-wal` and `history.sqlite-shm` files in the same directory, and ensure ownership is `10001:10001` before starting the service. Never replace the database while a process is still writing to it.

## Upgrades, rollback, and removal

Back up the database, Compose configuration, and collector configuration first. Collector releases are stored under `/opt/ugreen-ups-panel/releases/`; `current` points to the active release, and `previous` retains the previous release.

**Version 0.3.0 upgrades the database to schema 2. Rolling back to a version that only supports the old schema requires restoring the pre-upgrade database backup. Do not let the old application write directly to the upgraded database.** See the [release notes](docs/DELIVERY.md).

```sh
sudo sh scripts/install-collector.sh
docker compose up -d --build

# If you need to roll back the collector
sudo sh scripts/rollback-collector.sh
```

Rolling back the dashboard also requires a saved old image or the previous source version. Recreating the container preserves the history volume; check database compatibility before restoring across versions.

```sh
docker compose down
sudo sh scripts/uninstall-collector.sh
```

Removal preserves the history volume, snapshot, and collector release files. If usbmon was not loaded before installation, the script attempts a normal module unload; if it is in use, it remains loaded rather than being forcefully removed. Do not disable the original UPS driver to uninstall the dashboard.

## Frequently asked questions

**NUT works, but the dashboard has no data.** The original driver may not be reading complete `0x71` reports, or usbmon may be unavailable. Start with `journalctl -u ugreen-ups-collector.service -n 50 --no-pager`. Do not stop NUT or detach the USB interface to force access for the dashboard.

**Why is power blank, or different from my smart plug?** The single-installation calibration model is disabled by default. A smart plug measures AC input, while battery power and the NAS's DC input are different measurement locations with different conversion losses. The [calibration documentation](docs/calibration.md) explains the optional model, its assumptions, and its operating range.

**Does USB completion status `-2` indicate a UPS fault?** It is transport metadata. The validated driver can return complete reports in these completion events. The collector accepts them only when the status, endpoint, complete payload length, and field checks all pass.

**Why did telemetry stop after a NAS update?** Check whether the new kernel still provides a compatible usbmon interface and whether the original driver still generates complete reports. Other NAS services working normally does not prove that these capture requirements remain satisfied.

**Why are temperature, remaining runtime, and load percentage absent?** A chip having a sensing capability does not prove that the private USB report exposes it reliably. The dashboard does not fill those fields with speculative values.
